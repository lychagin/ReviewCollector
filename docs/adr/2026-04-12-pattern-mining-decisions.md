# ADR: Pattern Mining Skill — Ключевые решения

**Дата:** 2026-04-12  
**Статус:** Accepted  
**Контекст:** Проектирование подсистемы 2 (Pattern Mining) для Review Collector

---

## ADR-001: Гибридная архитектура (CLI препроцессор + Claude скилл)

**Решение:** Механическая работа (реконструкция тредов, нормализация, chunking) выносится
в отдельный CLI скрипт `preprocess-comments.mjs`. Анализ и синтез паттернов — исключительно
задача Claude через скилл `/mine-patterns`.

**Альтернативы:**
- Только скилл, Claude читает raw JSONL напрямую — отклонено: Claude тратит контекст на механику вместо анализа
- Полностью автономный скрипт с Claude API — отклонено: хуже качество, нет прозрачности

**Обоснование:** Опыт показал что чисто алгоритмические подходы не дают нужного качества
паттернов. LLM-анализ принципиально лучше для семантического понимания комментариев.
При этом Claude не должен тратить контекст на парсинг плоских JSONL — это механика.
Чёткое разделение позволяет тестировать препроцессор unit-тестами и перезапускать
его независимо от синтеза.

---

## ADR-002: Качество важнее скорости

**Решение:** Инструмент обрабатывает данные небольшими чанками (~30-50 тредов),
может работать минуты и часы. Скорость не является критерием.

**Альтернативы:**
- Обработать все комментарии за один LLM-вызов — отклонено: ограничения контекста, хуже качество

**Обоснование:** Результат (review-patterns.json) используется многократно, генерируется редко.
Качество паттернов напрямую влияет на качество работы Reviewer Agent.

---

## ADR-003: Два прохода синтеза

**Решение:** Pass 1 — грубые паттерны из чанков тредов. Pass 2 — обобщение, дедупликация,
финализация из всех raw паттернов.

**Обоснование:** Один проход не даёт нужного обобщения при большом объёме: паттерны из
разных чанков могут дублироваться или описывать одно и то же с разных углов. Два прохода
позволяют сначала извлечь сигнал, затем его очистить.

## ADR-004: Инкрементальная обработка с `mining-state.json`

**Решение:** `mining-state.json` хранит список уже обработанных файлов и накопленные
raw-паттерны. При повторном запуске обрабатываются только новые файлы из `processed/`.
Pass 2 пересинтезирует финальные паттерны каждый раз.

**Альтернативы:**
- Перезаписывать всё с нуля при каждом запуске — отклонено: теряем накопленные паттерны

**Обоснование:** Комментарии накапливаются со временем. Повторная обработка уже
проанализированных файлов — бессмысленная трата ресурсов. При этом Pass 2 всегда
запускается полностью для корректной дедупликации.

## ADR-005: JSON как source of truth + Markdown как view

**Решение:** `review-patterns.json` — единственный источник правды, машиночитаемый формат
для Reviewer Agent. `review-patterns.md` генерируется из JSON для удобства чтения человеком.

**Альтернативы:**
- Только Markdown — отклонено: сложно парсить программно
- Только JSON — отклонено: неудобно читать глазами

**Обоснование:** Reviewer Agent (подсистема 3) будет читать паттерны программно.
Одновременно разработчику нужно иметь возможность просматривать и ревьюить паттерны вручную.

---

## ADR-006: Скилл Claude Code, не автономный скрипт

**Решение:** Pattern Mining реализуется как скилл `/mine-patterns` в Claude Code.
Пользователь запускает его вручную, Claude управляет процессом, прогресс виден в чате.

**Альтернативы:**
- Standalone скрипт с Claude API — отклонено: менее прозрачно, сложнее вмешаться

**Обоснование:** Скилл позволяет наблюдать за процессом, корректировать при необходимости,
видеть что именно Claude выводит как паттерны. Это особенно важно на этапе настройки качества.
